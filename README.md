# LipatoS — Нагрузка

Foundry VTT v14 / D&D5e 6.0.6.

В модуле используются уже вычисленные системой D&D5e значения переносимого веса и пороги на встроенной полоске инвентаря. Своего параллельного счётчика предметов нет.

- Нагрузка — скорость −10 футов.
- Сильная нагрузка — скорость −20 футов и помеха на атаки, проверки и спасброски Силы, Ловкости, Телосложения.
- Перегрузка — скорость 0 и та же помеха.
- На любом уровне модуль снимает предыдущую ступень, чтобы штрафы не складывались.
- GM синхронизирует эффекты; игрок не может перемещать токен при скорости 0.
- В бою длина движения считается по встроенной в Foundry v14 стоимости пути и истории перемещений.
- Для игрока доступен метод API useDash(tokenDocument) — расходует действие «Рывок» один раз в ход и добавляет скорость к доступному перемещению; кнопка находится в модуле Buffs-Debuffs.
- Перемещение мастера не ограничивается.

**Примечание:** действие «Рывок» фиксируется этим модулем как потраченное. Учёт других использованных действий персонажа сторонними модулями не интегрирован.

Зависимости: Foundry 14, dnd5e 6.0.6. С модулем LipatoS — Buffs & Debuffs появляется панель и кнопка «Рывок».

## Иконки уровней нагрузки (v0.1.1)

- Жёлтая гиря — «Нагрузка» (−10 футов).
- Оранжевая гиря — «Сильная нагрузка» (−20 футов, помеха).
- Красная гиря — «Перегрузка» (скорость 0, помеха).

Все три изображения включены в установочный архив по путям `assets/icons/encumbrance-1.jpg` и далее. Модуль обновляет иконку существующего эффекта при следующей синхронизации, даже когда степень нагрузки не менялась.

## Защита выбора режима броска (v0.1.2)

Когда персонаж игрока имеет «Сильную нагрузку» или «Перегрузку» и выполняет атаку, проверку характеристики или спасбросок с использованием Силы, Ловкости или Телосложения, в штатном диалоге D&D5e:
- «Обычный» и «Преимущество» недоступны и тускнеют.
- При наведении на заблокированную область показано название дебаффа.
- «Помеха» остаётся активной.
- Даже при обходе окна сочетанием горячих клавиш соответствующий d20 принудительно бросается с помехой.
- Выбор другой характеристики в окне немедленно обновляет доступность кнопок.
- ГМ полностью освобождён от этих ограничений.
- Для бросков с Интеллектом, Мудростью или Харизмой режимы выбора не ограничиваются модулем.

## v0.1.3 — Рывок из Argon Combat HUD

- Совместимость с Argon Combat HUD CORE + DND5E: при нажатии на встроенную кнопку «Рывок» из HUD синтетическая карточка Argon регистрируется как использование действия «Рывок» в активном ходе персонажа.
- Учитываются также настоящие особенности «Рывок» с типом активации «Действие» через dnd5e.postUseActivity.
- Лимит движения текущего хода увеличивается на текущую скорость, включая штрафы нагрузки, не меняя скорость навсегда; после смены хода бонус не учитывается.
- Повторный «Рывок» за тот же ход не даёт вторую порцию движения; HUD помечает действие как потраченное.
- Чужие сообщения в чате не влияют на перемещение; идентификация синтетической карточки Argon выполняется по уникальной иконке, типу карточки, названию и текущему участнику боя.
- Обход ограничений GM остаётся без изменений.

Вызов рывка вне активного хода не выдаёт бонус. Действие «Рывок» с нулевой скоростью не позволяет перемещаться.

## v0.1.4 — Помеха на ВСЕ атаки

При «Сильной нагрузке» и «Перегрузке» у игрока обязательна помеха на **каждый бросок атаки** (оружие, дальняя атака, атака заклинанием), независимо от используемой характеристики, включая ИНТ, МДР и ХАР. Для проверок характеристик и спасбросков сохраняется ограничение только по СИЛ, ЛОВ и ТЕЛ.

- Штатные окна D&D5e блокируют «Обычный» и «Преимущество» и показывают название дебаффа при наведении.
- Принудительное значение `advantageMode = DISADVANTAGE` устанавливается в официальном хуке D&D5e `dnd5e.postBuildD20TestRollConfig` **до** создания броска. Поэтому работает и с быстрыми атаками через Argon Combat HUD, а также при обходе диалога горячими клавишами.
- После создания броска действует дополнительная проверка `dnd5e.postD20TestRollConfiguration`.
- Первая ступень «Нагрузка» не влияет на режим атак, ГМ не ограничен.

## v0.1.5 — исправления «Рывка» и совместимости атак

- Рывок Argon Combat HUD регистрируется по карточке действия игрока и активному участнику боя, с дополнительными способами найти токен из Argon, участника боя и выделенных токенов.
- Бонус скорости учитывается немедленно в локальном состоянии текущего хода (ключ: бой/раунд/ход/участник), даже когда запись флага токена отклоняется Foundry. Запись флага остаётся необязательным резервным сохранением.
- Ограничение перемещения считает текущую скорость + использованный «Рывок» в этом ходу; повторно получить бонус в тот же ход нельзя.
- Argon Movement HUD автоматически показывает увеличенную ёмкость перемещения после рывка (в клетках карты).
- Убран глобальный перехват `dnd5e.postBuildD20TestRollConfig`. Вместо него для атаки используется штатный `dnd5e.preRollAttack` и завершающий `dnd5e.postD20TestRollConfiguration`. Проверки характеристик и спасброски остаются в существующем обработчике.
- Реальные права доступа Foundry не изменяются. Системное предупреждение `DND5E.DocumentUseWarn` означает, что у пользователя нет уровня «Владелец» на используемый предмет/актёра; это проверяется самим D&D5e перед броском и исправляется назначением владельца актёра со стороны GM.

### Диагностика

Если «Рывок» не засчитывается, откройте F12 и проверьте сообщения `LipatoS Encumbrance: Argon Dash detected...`: в них показана причина, почему текущий участник боя не совпал с токеном на карточке.

## v0.1.6 — совместимость атак из Argon Combat HUD

- Исправление устаревшей ссылки на предмет или активность, сохраняемой кнопкой Argon после изменения/выбора токена. Перед использованием оружия модуль находит **принадлежащий текущему персонажу** предмет и соответствующую активность; даже если старый объект больше не имеет прав `isOwner`, новый объект работает корректно.
- Доступ разрешается только если **текущий актёр и настоящий найденный предмет действительно принадлежат пользователю** (Foundry `isOwner`); нет обхода серверной проверки, выдачи прав либо исполнения через ГМ.
- При отсутствии права `Владелец` показывается точное предупреждение с именем персонажа только один раз для данного предмета (вместо потока ошибок); ГМ должен назначить владение **токеном/актером, используемым игроком**.
- Рывок и движение не изменяются: интеграция Argon, текущие лимиты, блокировка скорости 0 и исключение ГМ сохраняются.
- Исправление включается только в D&D5e с Argon, не влияет на листы предметов и самостоятельные броски, не изменяет предметы в базе данных.
